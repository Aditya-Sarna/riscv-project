# RISC-V RV64I + Zba (Address Generation) Core

A complete 5-stage pipelined RISC-V RV64I processor implementation with the Zba address generation extension, including RTL, testbench, test program, and comprehensive documentation.

## Project Structure

```
riscv_core/
├── rtl/                    # SystemVerilog RTL files
│   ├── core.sv            # Top-level 5-stage pipeline processor
│   ├── regfile.sv         # 32 x 64-bit register file
│   ├── alu.sv             # 64-bit ALU with 10 operations
│   ├── imem.sv            # Instruction memory (ROM)
│   └── dmem.sv            # Data memory (RAM)
├── tb/                    # Testbench
│   └── tb_processor.sv    # SystemVerilog testbench with self-checking
├── software/              # Test programs
│   └── test.c             # C test program with Zba instructions
├── build/                 # Build artifacts (created during build)
├── design_diagram.txt     # ASCII art datapath diagram
├── design_diagram.drawio  # Draw.io source (open in app.diagrams.net)
├── design_diagram.pdf     # PDF diagram (generated by user)
├── DOCUMENTATION.md       # Comprehensive technical documentation
├── build_commands.txt     # Manual toolchain commands reference
├── Makefile               # Automated build system
├── generate_diagram_pdf.sh# Script to generate PDF diagram
└── README.md              # This file
```

## Quick Start

### Prerequisites

1. **RISC-V GNU Toolchain**
   ```bash
   # macOS (Homebrew)
   brew install riscv-tools
   
   # Or install from source
   # https://github.com/riscv-collab/riscv-gnu-toolchain
   ```

2. **SystemVerilog Simulator** (choose one)
   - Questa/ModelSim (Intel)
   - Synopsys VCS
   - Icarus Verilog (free, limited SV support)

3. **Optional: Draw.io CLI** (for diagram generation)
   ```bash
   brew install --cask drawio
   ```

### Build and Run (Using Makefile)

```bash
# 1. Build the hex file
make hex

# 2. Run simulation (default: Questa)
make sim

# 3. Or specify simulator
make sim SIM=vcs      # Use VCS
make sim SIM=iverilog # Use Icarus Verilog

# 4. Generate design diagram PDF
make diagram
```

### Manual Build (Using build_commands.txt)

If you prefer manual control:

```bash
# Compile C to ELF
riscv64-unknown-elf-gcc -march=rv64i -mabi=lp64 -O0 -nostdlib -Ttext=0x0 \
    software/test.c -o software/test.elf

# Extract binary
riscv64-unknown-elf-objcopy -O binary software/test.elf software/test.bin

# Generate hex file for simulation
hexdump -v -e '1/4 "%08x\n"' software/test.bin > rtl/imem.hex

# Run simulator (example: Questa)
vlog rtl/*.sv tb/tb_processor.sv
vsim -c tb_processor -do "run -all; quit"
```

## Design Overview

### Microarchitecture Features

- **5-Stage Pipeline**: IF → ID → EX → MEM → WB
- **64-bit Data Path**: Full RV64I support
- **Separate Memories**: Harvard architecture with separate IMEM/DMEM
- **Custom Zba Extension**: Address generation instructions (opcode 0x7F)

### Implemented Instructions

#### RV64I Base
- **R-type**: ADD, SUB
- **I-type**: ADDI, LD (load doubleword)
- **S-type**: SD (store doubleword)
- **J-type**: JAL

#### Zba Extension (Custom Encoding)
- **AG_ADD** (funct7=0x12): `rd = rs1 + rs2`
  - Purpose: Address generation via addition
  - Encoding: `0x12 << 25 | rs2 << 20 | rs1 << 15 | rd << 7 | 0x7F`

### Zba Instruction Examples in Test Program

The test program (`software/test.c`) includes three Zba instructions:

```c
// AG_ADD x10, x1, x5
asm volatile (".word 0x0050852FB");

// AG_ADD x11, x3, x4
asm volatile (".word 0x004185AFB");

// AG_ADD x12, x7, x6
asm volatile (".word 0x00638607B");
```

## Testbench

The testbench (`tb/tb_processor.sv`) provides:

- **Clock Generation**: 100 MHz (10ns period)
- **Reset Sequence**: 20ns initial reset
- **Self-Checking**: Automatically verifies memory write at address 0x100
- **Pass/Fail Report**: Displays test result
- **Simulation Duration**: 10,000ns (1000 clock cycles)

### Expected Output

```
Starting testbench
Checking dmem[32] = 0000000000001234
TEST PASSED: memory match
```

## Debugging Tips

### If Simulation Fails

1. **Check hex file exists**:
   ```bash
   make view-hex
   ```

2. **Verify disassembly**:
   ```bash
   make view-disasm
   ```

3. **Check memory initialization**:
   - Ensure `rtl/imem.hex` is in the correct format
   - One 32-bit hex word per line (little-endian)

4. **Use waveform viewer**:
   - Questa: `vsim -gui tb_processor`
   - Add signals and run simulation
   - Check PC progression, instruction flow

### Common Issues

| Issue | Solution |
|-------|----------|
| `imem.hex not found` | Run `make hex` to generate it |
| Test fails with wrong value | Check memory addressing (word vs byte) |
| Syntax errors in RTL | Ensure SystemVerilog-compatible simulator |
| Toolchain not found | Install RISC-V GNU toolchain, verify PATH |

## Design Philosophy

This implementation prioritizes:

1. **Clarity**: Well-commented, easy-to-understand code
2. **Functionality**: Correct operation over performance
3. **Verifiability**: Self-checking testbench
4. **Education**: Teaching-quality design patterns

### Known Limitations

- **No hazard detection**: Minimal forwarding/stalling
- **Subset of RV64I**: Only commonly-used instructions
- **Custom Zba encoding**: Uses opcode 0x7F (not standard)
- **No branch prediction**: Simple sequential execution

These are intentional simplifications for educational purposes.
